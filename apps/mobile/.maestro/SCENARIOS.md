# E2E 테스트 시나리오 (ClauseLens 모바일)

> 현재까지 구현된 기능(#12 촬영·#36 로그인·#38 프로필 …)의 end-to-end 시나리오.
> **문구 기준:** 홈 리디자인(#106·#112) 이후 UI(#123 동기화). 로그인 후 홈 앵커 = Hero **"계약서, 찍기만 하세요"**. 앱 문구를 바꾸는 PR은 `grep -rn "<옛 문구>" apps/mobile/.maestro`로 yaml·이 문서를 함께 갱신한다.
> 형식: **Given / When / Then**. 실행형 플로우는 같은 폴더의 Maestro `*.yaml`.
> appId: `com.chan.clauselens`

## 실행 방법 (Maestro)
```bash
# 설치(최초 1회)
curl -Ls "https://get.maestro.mobile.dev" | bash
# 로컬 백엔드 + docker(Postgres) 기동 필요 (로그인/세션 시나리오)
#   docker compose up -d && (cd apps/api && pnpm dev)
# dev build 앱이 시뮬레이터에 설치되어 있어야 함 (expo run:ios)
maestro test apps/mobile/.maestro/          # 전체
maestro test apps/mobile/.maestro/profile.yaml   # 개별
```

> ⚠️ **카카오 로그인은 계정 자격증명 입력이 필요**해 완전 자동화 불가. 로그인 웹뷰까지 자동 진행 후 **자격증명은 수동**(테스트 계정). 로그인 이후(프로필·FAQ·로그아웃)는 자동.
>
> ⚠️ **iOS 함정(2026-10-08 실측)**: maestro `clearState: true`는 앱 데이터만 지우고 **Keychain(expo-secure-store 세션)은 안 지움** → 로그인 상태가 유지됨. 그래서 `capture-gate`·`login`·`login-failure`의 "clearState=로그아웃" 전제가 iOS에서 성립 안 함 → **진짜 로그아웃(`logout.yaml`) 선행** 후 돌려야 로그인 화면이 나온다. 또 **수동 카카오 로그인이 60초를 넘기면** `login` 대기가 타임아웃될 수 있음(기능은 정상).

---

## S1. 미인증 게이트 (capture-gate)
- **Given** 저장된 세션이 없다(로그아웃 상태)
- **When** 앱을 실행한다
- **Then** 로그인 화면이 보인다: 타이틀 "ClauseLens", 버튼 "카카오로 시작하기"
- **And** 홈("계약서, 찍기만 하세요")으로 진입하지 않는다

## S2. 카카오 로그인 (login) — 일부 수동
- **Given** 로그인 화면 · 로컬 백엔드 기동
- **When** "카카오로 시작하기"를 탭한다
- **Then** 카카오 로그인 웹뷰(kauth.kakao.com)가 열린다
- **When** (수동) 카카오 계정으로 로그인/동의("계속하기")
- **Then** 백엔드 `/auth/kakao` 교환 성공 → JWT가 SecureStore에 저장
- **And** 홈("계약서, 찍기만 하세요")으로 진입한다
- **And** (백엔드 확인) `User`·`RefreshToken` 1행 생성, displayName은 실제 카카오 프로필

## S3. 세션 복원 (session-restore)
- **Given** 로그인된 상태(SecureStore에 세션 존재)
- **When** 앱을 종료 후 다시 실행한다
- **Then** 로그인 화면을 거치지 않고 **홈으로 바로 진입**한다(`/auth/me` 서버 검증 통과)
- **Edge** access가 만료/무효면 로그인 화면으로(토큰 문자열 존재만으로 인증하지 않음). ⚠️ access TTL 15분·자동 refresh 없음 → 로그인 15분 후 재실행하면 로그인 화면(실측 #123)

## S4. 프로필 진입 · 내 정보 (profile)
- **Given** 로그인된 상태, 홈
- **When** 헤더의 프로필 아이콘(접근성 라벨 "마이페이지")을 탭한다
- **Then** "마이페이지" 화면이 열린다(네이티브 헤더 + 뒤로)
- **And** 내 정보에 닉네임(실 프로필)과 "카카오 계정으로 로그인"이 표시된다

## S5. FAQ 아코디언 (profile)
- **Given** 마이페이지
- **When** "자주 묻는 질문"의 한 항목(예: "ClauseLens는 무엇을 해주나요?")을 탭한다
- **Then** 해당 답변이 펼쳐진다
- **When** 같은 항목을 다시 탭한다
- **Then** 답변이 접힌다

## S6. 1:1 문의 준비 중 (profile)
- **Given** 마이페이지
- **When** "1:1 문의"를 탭한다
- **Then** "준비 중" 안내 다이얼로그가 뜬다("곧 제공될 예정")

## S7. 로그아웃 (logout)
- **Given** 마이페이지
- **When** "계정 > 로그아웃"을 탭한다
- **Then** 확인 다이얼로그("로그아웃 하시겠어요?")가 뜬다
- **When** "로그아웃"을 확인한다
- **Then** 세션이 삭제되고 로그인 화면으로 돌아간다
- **And** (백엔드 확인) 해당 세션의 `RefreshToken`이 폐기된다

## S8. 촬영/갤러리 (capture) — 참고(#12)
- **Given** 로그인된 상태, 홈
- **When** "계약서 촬영"/"갤러리에서 선택"을 탭한다
- **Then** OS 카메라/사진 권한·피커가 뜬다(권한·피커 자체는 OS 영역, 스모크 수준)

## S9. 홈 빈 상태 UI (capture-empty)
- **Given** 로그인된 상태, 담긴 페이지 없음(재실행 시 draft 초기화)
- **When** 앱을 실행해 홈으로 진입한다
- **Then** 홈 빈 상태가 보인다: 헤더 "ClauseLens" · 칩 "무료 분석 N회 남음" · Hero "계약서, 찍기만 하세요"("불리할 수 있는 조항을 찾아 사진 위에 표시해 드려요.") · 버튼 "계약서 촬영"·"갤러리에서 선택" · 하단 Notice
- **Note** "계약서를 담아주세요"는 capture `EmptyState` 전용 문구로 현재 홈 경로에서 쓰이지 않음(#112)

## S10. FAQ 단일 열림 (faq-multi)
- **Given** 마이페이지 "자주 묻는 질문"
- **When** 항목1("ClauseLens는 무엇을 해주나요?")을 탭한다
- **Then** 답변1이 펼쳐진다("불리할 수 있는 조항을 찾아…")
- **When** 항목2("분석 결과는 법적 효력이 있나요?")를 탭한다
- **Then** 답변2가 펼쳐지고("법률 자문을 대체하지 않아요…") **답변1은 닫힌다**(한 번에 하나만 열림)

## S11. 로그아웃 취소 (logout-cancel)
- **Given** 마이페이지
- **When** "로그아웃"을 탭해 확인 다이얼로그("로그아웃 하시겠어요?")에서 "취소"를 누른다
- **Then** 로그아웃되지 않고 마이페이지에 그대로 남는다(세션 유지)

## S12. 프로필 뒤로가기 → 홈 (profile-back) — best-effort
- **Given** 마이페이지
- **When** 뒤로(iOS 좌측 엣지 스와이프)한다
- **Then** 홈("계약서, 찍기만 하세요")으로 돌아온다
- **Note** iOS 네이티브 back 제스처는 시뮬레이터에서 브리틀 → 스와이프 실패 허용(수동 확인 병행)

## S13. 갤러리에서 페이지 추가 (capture-add-page) — 반자동
- **Given** 로그인된 상태, 홈 빈 화면
- **When** "갤러리에서 선택"을 탭하고 OS 피커에서 사진을 **(수동)** 고른다
- **Then** 2열 그리드로 전환되어 헤더 "담은 페이지 1장" · 썸네일(접근성 "1페이지 미리보기") · 버튼 "분석하기" · "+ 추가" 셀(접근성 "페이지 추가")이 보인다
- **Note** OS 사진 피커 선택은 수동(자동화 브리틀). 선택 이후 화면은 자동 검증

## S14. 페이지 삭제 → 빈 상태 (capture-remove-page) — 반자동
- **Given** 페이지 1장이 담긴 상태(S13처럼 수동 추가)
- **When** 썸네일 우상단 X(접근성 라벨 "1페이지 삭제")를 탭한다
- **Then** 페이지가 사라지고 홈 빈 상태("계약서, 찍기만 하세요")로 돌아온다

## S15. 페이지 순서 변경 (드래그) — 문서만(수동 관측)
- **Given** 페이지 2장 이상(각각 수동 추가)
- **When** 썸네일을 길게 눌러 드래그로 순서를 바꾼다("길게 눌러 순서 변경")
- **Then** 썸네일 번호 배지(1·2)가 새 순서대로 재정렬된다
- **Note** draggable-flatlist 롱프레스 드래그 + 2장 수동 피커라 Maestro 자동화 브리틀 → **yaml 없이 수동 관측**. 상태 전이(setPages)는 후속 draftStore 단위 테스트로 커버 검토

## S16. 로그인 실패 — 친화 문구 노출 (login-failure) — 반자동
- **Given** 로그인 화면 · **백엔드(/auth/kakao)가 응답하지 않음**(docker/api off)
- **When** "카카오로 시작하기" → (수동) 카카오 인증까지 완료
- **Then** 토큰 교환이 실패하고 **친화 문구**가 뜬다("네트워크 연결을 확인해주세요") — 원문(`Network request failed` 등) 미노출
- **And** 홈으로 진입하지 않고 로그인 화면에 남아 재시도할 수 있다
- **Edge** 사용자가 카카오 로그인을 **취소**하면 에러 문구를 띄우지 않는다(조용히 로그인 화면 유지)
- **Note** 매핑 로직 4케이스는 단위 테스트(`lib/loginError.test.ts`)로 커버 — yaml은 화면 노출만 확인

## S17. 권한 거부 안내 (permission-denied) — 반자동
- **Given** 로그인된 상태, 홈 빈 화면 · 카메라/사진 권한 **미허용**
- **When** "계약서 촬영"(또는 "갤러리에서 선택")를 탭하고 OS 권한 다이얼로그에서 **거부**한다
- **Then** 앱이 안내 다이얼로그를 띄운다("카메라 권한이 필요해요" / 사진이면 "사진 권한이 필요해요")
- **And** "설정 열기"를 누르면 OS 설정으로 이동한다(`Linking.openSettings`)
- **And** 페이지가 추가되지 않고 빈 화면이 유지된다
- **Note** OS 권한 다이얼로그·설정 앱 전환은 시뮬레이터에서 브리틀 → yaml은 **반자동**(권한 거부 수동). 안내 로직(문구·설정 열기)은 단위 테스트(`lib/permission.test.ts`)가 확정

## S18. 업로드 (upload) — 반자동 (#61)
- **Given** 로그인된 상태 · 로컬 백엔드(API)+MinIO 기동 · Draft에 이미지 1장 이상(피커 수동)
- **When** "분석하기"를 탭한다
- **Then** 진행 화면 "계약서를 올리고 있어요"(업로드 준비 중… → "N장 중 n장 전송"/"전송 중…" → "서버 확인 중…") → 업로드 확정 즉시 분석 모드 **"계약서를 분석하고 있어요"**로 전환(별도 "업로드 완료" 문구 없음, #108)
- **And** (백엔드 확인) Document.status=uploaded, Page.finalKey 채택
- **Edge** 무료 0회 계정은 업로드 확정 후 분석 요청 403 → "무료 분석 횟수가 없어요"(업로드 자체는 성공)
- **Edge** 실패 시 "분석에 문제가 생겼어요" + "다시 시도" 버튼으로 미확정 페이지만 재발급→재전송→complete(멱등)
- **Note** 로그인(카카오)·사진 선택 수동. 오케스트레이션 로직은 단위(`upload/*.test.ts`)로 커버. 서버 계약은 백엔드 MinIO 실측(#15)로 확정

## S19. 분석 요청·상태 폴링 (analysis) — 반자동 (#63)
- **Given** 로그인된 상태 · 로컬 API+worker+Redis+Postgres 기동 · Draft 이미지 업로드까지 완료
- **When** 업로드가 확정되면 분석이 **자동 시작**된다(별도 탭 불필요)
- **Then** "계약서를 분석하고 있어요"("분석 요청 중…" → "분석 중…"/"N페이지 중 n페이지 완료") → **"분석이 끝났어요"**
- **And** (백엔드 확인) Document.status=done, AnalysisJob.status=done, PageAnalysis 전부 done
- **And** 상태는 SSE로 실시간 반영되며, 앱 재진입 시 GET로 복원된다(진실의 기준)
- **Edge** 일부 페이지 분석 실패 시 **"일부만 분석됐어요"**(partial, 버튼 "분석된 결과 보기"). 전체 실패면 "분석에 문제가 생겼어요"(failed)
- **Note** 로그인·사진 선택 수동, 이번 슬라이스는 **stub worker**(실제 OCR은 TASK-004). 오케스트레이션·SSE·역순 도착 방어는 단위(`analysis/*.test.ts`), 서버 전 경로는 백엔드 실측(#63, done/partial/SSE)로 확정

## S20. 결과·위험조항 하이라이트 (result) — 반자동 (#73)
- **Given** 로그인 · 로컬 API+worker(실제 Vision+Claude)+Redis+Postgres+MinIO 기동 · 분석 완료(또는 부분 완료) 상태
- **When** 완료 화면에서 **"결과 보기"**(partial이면 "분석된 결과 보기")를 탭한다
- **Then** 결과 화면 진입: 상단 **"분석 결과"** + 원본 이미지 위 위험조항 하이라이트 + 조항 목록(종류·위험도·설명·근거 원문)
- **And** 목록의 조항을 탭하면 해당 조항의 **모든 하이라이트**가 강조된다(선택 표시는 위험도 색과 별도: 테두리·접근성 selected)
- **And** 여러 페이지면 "이전/다음"으로 전환(전환 시 선택 해제)
- **Edge** 위험조항 0건 → "확인이 필요한 조항을 찾지 못했습니다"(정상) · 이미지 없음(재진입) → 목록만(우아한 저하) · 로컬↔서버 크기 불일치 → 하이라이트 생략·목록 유지 · 결과 격리(현재 사용자·문서 일치 시만 표시)
- **Note** 로그인·사진 선택 수동. 좌표 변환·클램프·크기 정합은 단위(`result/lib/coordinateTransform.test.ts` 18개)로 커버. **EXIF 방향 1~8 오버레이 일치는 비대칭 fixture로 시뮬/기기 실측(별도)**. yaml(`result.yaml`)은 결과 화면 진입까지 자동, 하이라이트·조항 내용은 육안 확인

## S21. 무료 잔량 표시 · 403 안내 (entitlement) — 반자동 (#94)
- **Given** 로그인된 상태 · 로컬 API+Postgres 기동
- **When** 마이페이지에 진입한다
- **Then** "내 이용 · **남은 무료 분석 N회**"(서버 `GET /me/entitlement` 값)가 표시된다. 로딩 중 스피너, 조회 실패 시 "불러오지 못했어요 · 다시 시도"(0회로 대체하지 않음)
- **And** 분석 접수·완료 후 프로필 재진입 시 잔량이 갱신된다(접수=예약, 완료=확정/해제)
- **Edge(403)** 무료 횟수 소진 상태에서 "분석하기" → 전용 무료 소진 화면 **"무료 분석 횟수가 없어요"** · "확인"·"남은 분석 상태 보기"(#114, 404·409·네트워크 오류와 구분)
- **Edge(계정 전환)** 로그아웃/다른 계정 로그인 시 이전 사용자 잔량이 노출되지 않는다
- **Note** 표시는 profile.yaml로 자동(라벨 확인). **403·계정 전환·접수/완료 갱신은 백엔드 잔량 seeding 필요 → 반자동/실측(별도)**. 응답 계정 격리·겹친 refresh·403 분기·zod 검증은 단위(`entitlement/*.test.ts`, `analysis/useAnalysis.test.ts`)로 커버. 서버 집행은 #90 백엔드 실측

## S22. 분석 기록 재열람 — 홈 최근 진입 버튼 · 목록 · 조항 재열람 (documents) — 반자동 (#96, #112)
- **Given** 로그인된 상태 · 로컬 API+Postgres 기동 · (진입 버튼 분기는) 분석 완료 문서 존재(보관 7일 이내)
- **When** 홈(빈 상태)에 진입한다
- **Then** 기록이 있으면 진입 버튼 **"최근 분석 N건"**(접근성 "최근 분석 N건 모두 보기"), 0건이면 온보딩(3단계 "촬영·분석·하이라이트" + "분석 결과는 참고용이며 법률 자문을 대체하지 않아요.") — 홈 인라인 최근 섹션은 없음(#112)
- **And** 버튼 탭 → /recent "최근 분석" 전체 목록(완료순, 당겨서 새로고침·무한 스크롤, "분석 결과는 7일 동안 보관돼요.", 문서 행 "계약서 · N장" · 상대일 · 위험 N건 · "**N일 후 삭제**"/"오늘 만료", 하단 구독 카드). 목록 0건이면 "아직 분석한 계약서가 없어요"
- **And** 문서 행 탭 → 결과 화면에서 **조항 재열람**(이미지 하이라이트 복원은 후속 이슈) — 앱을 나갔다 들어와도 서버에서 다시 받아 표시
- **Edge(보관 경과)** retainUntil 지난 문서 재열람 시도 → **"보관 기간이 지났어요"** 안내 + 목록에서 제거(410). 목록 자체에도 노출되지 않음
- **Edge(계정 전환)** 로그아웃/다른 계정 로그인 시 이전 사용자 목록이 노출되지 않는다
- **Note** 진입 버튼→목록(기록 있음)·온보딩(0건)은 recent.yaml이 조건 분기로 자동. **문서 행 탭 재열람·410·계정 전환은 백엔드 seeding 필요 → 반자동/실측(별도)**. 보관 설정·목록 집계·커서·접근 차단은 db 통합(`packages/db/test/recall.integration.mjs`)·api 단위(`documents*.spec.ts`), 앱 store 격리·배지·410 제거는 단위(`documents/*.test.ts`)로 커버

## S23. 분석 결과 장기 보관 전환 — 저장하기 (documents) — 단위 커버(#163, TASK-006 ②)
