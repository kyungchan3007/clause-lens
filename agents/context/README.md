# Context Engineering — "무엇을 알려주는가"

에이전트가 **필요한 만큼만, 필요한 때에** 정보를 받도록 문서를 구성하는 계층입니다.
컨텍스트 창은 유한하고, 잘못된/과잉 정보는 나쁜 코드로 이어집니다.

## Progressive Disclosure (점진적 공개)

항상 로드되는 문서는 **작게**, 세부는 링크로 위임합니다.

```
AGENTS.md (항상 로드, 짧게)
   └─▶ agents/README.md (아키텍처)
         └─▶ intent/ context/ harness/ orchestration/ (필요할 때만)
               └─▶ 개별 스펙·상세 문서 (해당 태스크일 때만)
```

**규칙**: `AGENTS.md`에 세부를 쌓지 마세요. 새 정보는 적절한 하위 문서에 넣고 링크만 겁니다.

## 이 계층의 문서

| 문서 | 용도 |

| 도메인 문서 6개 | 도메인별 계약·불변조건. `domain-map.md`에서 링크로 진입 |

> 도메인 문서(`auth-entitlement.md` 등 6개)는 이 폴더에 **평평하게** 둡니다. 서브디렉터리 없이
> `domain-map.md`를 유일한 인덱스로 삼아 탐색 hop을 최소화합니다.

## 메모리 (Memory)

- **저장소 지식**(코드·아키텍처·규칙)은 이 `agents/` 트리에 파일로 둡니다 — 두 AI 공용.
- **세션 간 학습**(예: "Expo v57에서 X API는 Y로 바뀜")이 생기면
  1) 관련 하위 문서에 반영하고, 2) [JOURNAL.md](../JOURNAL.md)에 근거를 남깁니다.
- 도구별 개인 메모리(Claude의 `~/.claude` 등)에 **공용 규칙을 두지 마세요.** 상대 AI가 못 봅니다.

## 좋은 컨텍스트의 원칙

1. **단일 출처** — 같은 사실을 두 곳에 쓰지 않는다(드리프트 방지).
2. **가까이 둔다** — 코드 옆 규칙은 해당 폴더 문서에, 전역 규칙은 여기에.
3. **최신성 표시** — 오래되면 틀린 문서는 위험하다. 바뀌면 즉시 갱신.
