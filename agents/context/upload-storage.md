# Upload & Storage Domain Guide

## 책임

- NestJS에서 Presigned URL과 imageKey를 발급한다.
- Expo 앱이 S3에 이미지 바이너리를 직접 업로드한다.
- 업로드 완료 후 API가 문서 페이지와 imageKey를 연결한다.

## 표준 흐름

1. 앱이 파일 메타데이터와 함께 업로드 URL을 요청한다.
2. API가 소유권과 파일 정책을 검증하고 URL을 발급한다.
3. 앱이 S3에 직접 업로드한다.
4. 앱이 API에 업로드 완료를 전달한다.
5. API가 객체 존재와 메타데이터를 확인한 뒤 페이지에 연결한다.

## 불변 조건

- 클라이언트가 임의의 S3 key를 최종 결정하지 않는다.
- Presigned URL은 짧은 만료 시간을 사용하고 특정 객체와 작업으로 범위를 제한한다.
- 허용 확장자만 믿지 않고 MIME, 크기, 실제 디코딩 가능 여부를 검증한다.
- 업로드 완료 전에는 OCR 작업을 등록하지 않는다.
- Presigned URL과 원본 이미지 내용을 로그에 남기지 않는다.

## 오류 처리

- URL 만료: 새 URL을 요청하고 재시도한다.
- 네트워크 중단: 진행률과 재시도 UI를 제공한다.
- 업로드 성공·완료 통지 실패: 동일 imageKey로 완료 통지를 재시도한다.
- 잘못된 이미지: 페이지에 연결하지 않고 사용자에게 재촬영을 안내한다.

## 검증

- 대용량 또는 허용하지 않은 파일이 거부된다.
- 만료 URL 재발급 후 정상 업로드된다.
- 완료 통지 중복 호출이 페이지를 중복 생성하지 않는다.
