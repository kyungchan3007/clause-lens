# Observability — 무슨 일이 있었는지 남기기

두 AI가 비동기로 협업하므로, **상대가 무엇을 왜 했는지** 볼 수 있어야 합니다.
관찰 가능성이 없으면 두 AI는 서로의 작업을 덮어씁니다.

## 공유 저널 (필수)

작업이 끝나면 [`../JOURNAL.md`](../JOURNAL.md)에 **한 항목을 append** 합니다. 형식:

```md
## YYYY-MM-DD HH:MM · <Claude|Codex> · #TASK-xxx
- **무엇**: 한 줄 요약
- **왜**: 근거(스펙/이슈)
- **파일**: 바꾼 주요 파일
- **게이트**: checks.sh PASS/FAIL
- **다음/주의**: 상대 AI가 알아야 할 것 (있으면)
```

규칙:
- 저널은 **append-only**. 남의 항목을 수정·삭제하지 않는다.
- 태스크를 `done`으로 바꾸는 것과 저널 기록은 **한 세트**.

## 런타임 로그 (앱 코드)

- 임시 `console.log`는 커밋 전에 제거하거나 의미 있는 로그로 승격.
- 업로드/분석 상태(`PROCESSING`/`COMPLETED`/`FAILED`) 전이는 사용자에게 보이는 상태로 반영.

## 피드백 루프 연결

저널·게이트에서 **스펙과 현실의 괴리**가 드러나면 → [Intent](../intent/README.md)의 스펙을 갱신.
반복되는 실수(예: 특정 Expo API 오용)는 → 관련 [Context](../context/README.md) 문서에 주의로 추가.
이것이 아키텍처가 학습하는 방식입니다.
