# PRD — 애매한 요청 대책: 질문 먼저 규칙 + prd "애매한 곳·가정" 필수 칸

- **작성**: Claude · **날짜**: 2026-10-09
- **설계 근거**: harness-lab 0024·0025·0026·0028·0030

## 1. 문제 (Problem)
- AI가 요청의 빈칸을 추측하면 의도가 흔하지 않을 때 거의 틀린다(흔한 41% → 흔하지 않은 4%).
- 묻고 답받고 이어가면 의도와 무관하게 맞는다(대화형 100%). 하지만 "애매하면 묻는다" 규칙이 없다.
- 지시만으로는 가정을 잘 안 남긴다 → 필수 칸이면 남는다(몰래 지어냄 95%→57%).

## 2. 목표 (Goals)
- G1. **질문 먼저 규칙**: 요청에 정해지지 않은 값·용어가 있으면 구현 전에 질문해 답을 받는다(loop.md·AGENTS.md).
- G2. **prd 7번 칸을 "애매한 곳·가정" 필수 칸으로** + `checkFolderPrd` 검사(도입 번호 이후, 괄호 표시 요구).

## 3. 목표가 아닌 것 (Non-goals)
- N1. "확인 필요" 남으면 완료 차단(harness-lab 미실험) · N2. 설계/구현 모델 분리 · N3. 지난 spec 소급 · N4. loop.md·AGENTS.md 외 문서 동기화.

## 4. 사용자 흐름 (User Flow)
1. 요청에 빈칸(금액 기준·끝수·등급 판별·입력 모양 등)이 있으면 질문 목록으로 정리해 답을 받는다.
2. "커밋할까요?" 같은 진행 확인은 질문 목록이 아님 — 요구의 빈칸만.
3. prd 7번 칸에 각 줄 끝 `(가정)`·`(확인 필요)`·`(확인됨: 답)`. 답 받으면 줄 끝 표시를 `(확인됨: 답)`으로.

## 5. 성공 지표 (Success Metrics)
- 도입 이후 prd 7번 칸이 표시와 함께 채워짐. 템플릿 그대로·표시 없는 줄은 검사가 거부. `checks.sh` PASS.
