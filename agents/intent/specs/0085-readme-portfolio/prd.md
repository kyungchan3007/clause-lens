# PRD — README 포트폴리오용 재구성

- **상태**: draft
- **작성**: Claude  ·  **날짜**: 2026-11-10
- **이슈:** #207
- **관련 태스크**: 문서(README 리뷰어용 정돈)

## 1. 문제 (Problem)
README가 기능·구조 위주라, 채용 리뷰어가 첫 화면에서 "어떤 기술 문제를 어떻게 해결했나"를 바로 파악하기 어렵다. 아키텍처 mermaid는 렌더 품질이 일정하지 않다.

## 2. 목표 (Goals)
- G1. 사용자 초안 구조로 README를 교체한다.
- G2. 상단 `📌 해결한 문제` 3줄과 `🎯 핵심 기술` 3항목을 같은 순서(동시성 → 좌표 정합 → 비동기 파이프라인)로 1:1 대응시킨다.
- G3. 아키텍처를 mermaid 대신 이미지로 보여준다.

## 3. 목표가 아닌 것 (Non-goals)
- N1. 코드·의존성 변경 아님(문서·이미지만).
- N2. 앱 화면 스크린샷 제작 아님(파일이 없어 주석 처리, 추가 시 해제).

## 4. 사용자 흐름 (User Flow)
리뷰어가 README 첫 화면에서 해결한 문제 3줄 → 핵심 기술 상세 → 아키텍처 이미지 순으로 읽는다.

## 5. 성공 지표 (Success Metrics)
- 요약 3줄과 핵심 기술 3항목의 번호·순서가 일치.
- 수치는 기존 기록(통합 테스트·JOURNAL)에 있는 것만 사용.

## 6. 제약 (Constraints)
포트폴리오 문체(격식체, 캐주얼 라벨 금지). 사용자 초안 문구는 유지하고 순서·보강만.

- [x] 아키텍처 이미지 추가, mermaid 제거
- [x] 링크된 문서 경로가 실제로 존재
- [x] `bash agents/harness/evals/checks.sh` ALL PASS

## 7. 애매한 곳·가정 (Open Questions)
- 요약은 "배운 점"이 아니라 경력자 관점의 해결한 문제로 쓰고, 상세는 핵심 기술에서 푼다 (확인됨: 사용자 지시)
- 아키텍처는 mermaid 금지, 이미지로 만든다 (확인됨: 사용자 지시)
- 초안의 화면 스크린샷 3장은 저장소에 없어 주석 처리하고, 파일 추가 시 해제한다 (가정)
