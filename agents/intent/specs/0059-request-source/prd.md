- **이슈:** #155

## 1. 문제 (Problem)
원래 요청(이슈 본문)이 단계마다 "요약"으로 전달되면 결함을 못 잡는다.
- harness-lab 실험(쿠폰 과제·Haiku 4.5·3회): 역할 분리 + 요약 전달 → 정답률 **46%**, 놓친 결함 **34개**.
  같은 조건에 **원문 고정 장치**(요청 원문 파일 + 원문 대조 판정)만 더하면 → 정답률 **100%**, 결함 **0**.
- 실패 메커니즘: 조율 AI가 원문 대신 요약을 넘김 → 설계 AI가 규칙을 지어냄 → 검사 AI가 그 지어낸 설계를
  기준으로 통과시킴. **검사자가 따로 있어도 판단 기준이 원문이 아니면** 결함을 놓친다.
- ClauseLens의 같은 위험 지점:
  - `.github/scripts/pr-ai-review.mjs` — 리뷰 입력에 PR 제목·본문·커밋·코드 변경은 있으나 **연결 이슈(원문)는 없음**.
    PR 작성자의 요약을 기준으로 리뷰.
  - Claude ↔ Codex 교차 검증 — 원문 대신 요약이 전달될 수 있음.
  - spec `prd.md` — 이슈를 옮겨 적은 것이라, 옮기며 틀려도 이후 단계는 prd만 본다.

## 2. 목표 (Goals)
- G1. 태스크 폴더에 **원문 파일 `request.md`**(이슈 본문 복사)를 고정하고, 한 번 생성되면 수정 차단.
- G2. **PR AI 리뷰가 연결 이슈 원문을 입력으로 받고**, 리뷰에 "원문 규칙별 대조" 결과를 포함.
- G3. **교차 검증(Codex) 지시에 "판정 기준은 원문, prd·설계는 옮긴 것"** 을 명시.
- G4. 적용 전후 **측정 방법 정의·기록**.

## 3. 목표가 아닌 것 (Non-goals)

- N2. 체크박스 동기화 #153, 잔재 폴더 게이트 오탐 #154 (이미 머지됨).
- N3. harness-lab의 숨은 채점·실험 실행 장치 이식(연구용).

## 4. 사용자 흐름 (User Flow)
- 착수: `pnpm request <이슈>` → `agents/intent/specs/<폴더>/request.md` 생성(이슈 본문 복사, 이미 있으면 덮어쓰지 않음).
- 작업 중: 생성된 `request.md`를 수정하려 하면 가드가 차단(불변).
- PR: AI 리뷰가 연결 이슈 본문을 읽어 코드 변경을 **원문 요구사항별로 대조**한 결과를 코멘트에 포함.
