## PRD

### 1. 문제
- 4a 백엔드가 위험 조항과 원본 이미지 좌표를 만들어 앱까지 전달하지만, **이를 보여줄 화면이 없다.**
- 현재 분석이 끝나면 앱에는 동작 없는 "분석 완료" 버튼만 뜬다(결과·하이라이트 화면 미연결).
- 사용자는 "무엇이 위험한지"와 "원문 어디에 있는지"를 확인할 수 없다 — 제품의 핵심 가치가 화면으로 닫히지 않은 상태.

### 2. 목표
- **G1** 분석 완료 후 결과 화면에서 **원본 이미지 위에 위험 조항을 하이라이트**로 표시.
- **G2** 조항 목록(종류·위험도·설명·근거 원문) 표시 + **목록 → 하이라이트 연동**(항목 탭 → 해당 조항의 **모든 박스** 강조·이미지 영역 보이기). 역방향(박스 탭 → 목록)은 후속.
- **G3** 원본 좌표 → 화면 좌표 **정확 변환**(이미지 contain-fit) + **EXIF 방향 일치**.
- **G4** 위험도 표현: 색상 토큰(높음/보통/낮음) + **색상만이 아니라 라벨·아이콘 병행**(접근성·정책 02).
- **G5** 예외 상태 처리: 위험조항 0건(정상)·부분 실패·이미지 없음(재진입)·에러.
- **G6** 다중 페이지 결과 탐색(페이지 전환).

### 3. 비목표 (이번에 안 함)
- 분석 후 **이미지 교체·부분 재분석** → TASK-007.
- **앱 재시작 후 재열람·저장 문서 열람**(서버 이미지 다운로드 필요) → TASK-006/후속.
- 조항 **편집·공유·PDF 내보내기** → 후속.
- **무료 횟수 실차감** → TASK-005.
- 조항 원문 **재-OCR·하이라이트 정밀 보정(문자 단위)** → 후속(현재는 문단 박스 단위).

### 4. 제약 (Guardrails)
- **서버 = 진실**: 앱은 서버가 준 조항·좌표를 **표현만** 하고 위험 여부를 스스로 판단하지 않는다.
- **로그 금지**: 좌표·원문(sourceText)·토큰·이미지 경로를 로그에 남기지 않는다.
- **색상 단독 금지**: 위험도는 색 + 라벨/아이콘을 함께 제공(정책 02).
- **FSD 경계**: feature → feature 직접 import 금지, 조합은 app 레이어에서(결과 화면도 동일).
- **shared-first UI**: 위험도 배지 등 제네릭·표현용 요소는 공용 UI로 승격.

### 5. 사용자 흐름
1. 분석이 완료(또는 부분 완료)되면 결과 화면으로 갈 수 있는 버튼이 활성화된다.
2. 결과 화면: 상단에 분석된 이미지 + 그 위에 위험 조항 하이라이트, 하단에 조항 목록.
3. 목록의 조항을 탭하면 이미지의 해당 하이라이트(그 조항의 모든 박스)가 강조된다(역방향 박스 탭→목록은 후속).
4. 페이지가 여러 장이면 페이지를 전환해 각 페이지 결과를 본다.
5. 위험 조항이 없으면 "확인이 필요한 조항이 없습니다"를 정상 상태로 보여준다.

## SDD

### ① 데이터 원천
- **결과 데이터는 이미 앱에 있음**: 분석 스토어(`analysisStore.pages`)가 완료 시 페이지별 `clauses`·`boxes`·`imageWidth/imageHeight`를 모두 보유. **새 서버 조회 불필요**(주 흐름).
- **이번 범위 = 세션 내 열람만**: 스토어에 완료 결과가 있을 때만 결과 화면에 진입(같은 세션). **스토어 소실(앱 재시작) 후 서버 재조회는 TASK-006로 이관**(재열람·저장 문서와 함께). `useAnalysis.start()`는 POST 분석 요청이므로 조회 전용 진입에 재사용하지 않는다.
- **결과 격리(필수)**: 결과 화면은 `documentId`를 받아 **현재 로그인 사용자 + 스토어의 `documentId`가 요청 `documentId`와 일치**할 때만 표시한다. 불일치·계정 변경·새 문서 시작 시 결과를 숨기고, 늦게 도착한 응답은 (소유자·문서·실행 세대)로 폐기한다. 스토어 접근은 **app 레이어가 주입**(feature→feature import 금지).
- **이미지 원천(갭)**: 서버 이미지 다운로드 엔드포인트가 없다(→ TASK-006 후속). 이번 범위는 **세션 한정**으로, 업로드 시점에 **불변 스냅샷**을 남겨 결과 화면에서 그대로 쓴다.
  - 스냅샷 = `{ ownerUserId, documentId, pageId, revision, localUri, width, height }`. **업로드 확정 시점에 고정**하고 이후 초안 URI 교체(페이지 교체)에 영향받지 않는다.
  - `pageId → 현재 초안 localUri`로 되짚거나 **순서로 매칭하지 않는다**(교체 시 어긋남).
  - **폐기 조건**: 새 문서 시작·로그아웃·계정 변경 시 스냅샷 폐기. **revision 불일치**면 미리보기를 쓰지 않는다.
  - 앱 재시작·재진입으로 스냅샷이 없으면 이미지 없이 목록만 표시(우아한 저하, ⑦).

### ② 계약
- **신규 서버 계약 없음** — 4a 계약(조항·박스·이미지 크기) 재사용. 박스 좌표계 = **원본 EXIF 정규화 upright 픽셀**, 크기 = `imageWidth/imageHeight`(원본 upright 실측).
- 앱 내부 표시용 타입만 신규(선택 조항 상태 등).

### ③ 구조 (FSD · `features/result/`)
- `ui/ResultScreen` — 이미지 + 오버레이 + 조항 목록 조합, 페이지 전환.
- `ui/HighlightOverlay` — 박스 오버레이 렌더(⑤ 결정에 따라 Skia 또는 SVG).
- `ui/ClauseList` · `ui/ClauseCard` — 조항 목록/카드.
- `model/useResultData` — (app이 주입한) 조항 + 이미지 스냅샷 + 선택/페이지 상태. **선택 키 = `pageId + revision + clauseId`**, 페이지 전환 시 선택 해제. 선택 시 대표 박스로 이미지 영역 보이기.
- `lib/coordinateTransform` — 원본 → 화면 contain-fit 변환(순수 함수, 단위 테스트 대상).
- **공용 승격 후보**: 위험도 배지(색+라벨+아이콘)는 `packages/ui`로.
- **app 레이어**: 결과 화면 라우트 등록 + `PageList`에 결과 보기 콜백 주입(feature→feature import 금지).

### ④ 좌표 변환 (원본 → 화면)
- 표시 영역 크기를 실제 렌더 시점에 측정(onLayout).
- contain-fit: `scale = min(viewW / imageWidth, viewH / imageHeight)`, 레터박스 오프셋 계산.
- 박스 변환: `screenX = x*scale + offsetX`, `screenY = y*scale + offsetY`, 폭·높이도 scale 적용.
- **정합 기준 = 서버 `imageWidth/imageHeight` 공간(확정).** 표시 이미지는 자연 비율로 contain 표시하고, 로컬 이미지 intrinsic 크기는 **대응 검증용**으로만 쓴다(강제 stretch·축 교환 금지).
- **불일치 처리**: 로컬 크기 ≠ 서버 크기면(방향·다른 이미지·메타 해석 문제일 수 있음) 이미지는 자연 비율로 표시하되 **오버레이는 중단하고 목록만 유지**한다.
- **이미지 + SVG는 같은 콘텐츠 wrapper**에 두고 중앙 contain을 공유한다(부모 padding·별도 bounds로 어긋나지 않게).
- 서버 픽셀 → 레이아웃 단위 변환은 **한 번만** 적용(`PixelRatio`를 추가로 곱하지 않음). SVG `viewBox`로 추가 스케일하지 않는다.
- **클램프 = 원본 박스 ∩ 이미지 영역 교집합**으로 계산(폭·높이를 따로 자르지 않음). 교집합 면적 0은 버린다.
- viewport 크기가 0이거나 이미지 로드·정합 확인 전이면 박스를 그리지 않는다. 화면 크기 변경 시 재계산.

### ⑤ 오버레이 렌더 방식 — **react-native-svg 확정**
- RN `<Image>` 위에 같은 wrapper의 `<Svg>` + `<Rect>`(선언적, 이미 공용 아이콘에서 사용 중, 탭·강조 단순).
- Skia로의 전환은 **확대·제스처 도입** 또는 **측정된 렌더링 병목**이 있을 때만 검토(둘 다 이미 의존성에 있음). 다른 문서의 "Skia 고정" 표현도 함께 정리.

### ⑥ 위험도 색상·표현
- 토큰에 위험도 색 추가: 높음/보통/낮음(`semantic`). 라이트/다크 모두 정의.
- 배지 = 색 + 한국어 라벨 + 아이콘(색상 단독 금지, 정책 02).
- 조항 종류(9종)는 한국어 라벨 매핑.

### ⑦ 오류·상태 (엄격 구분)
- **정상 0건**: `status=done && analysisComplete===true && Array.isArray(clauses) && clauses.length===0` 일 때만. 문구는 범위를 제한하고 참고 고지 포함 — "이번 분석에서 확인이 필요한 조항을 찾지 못했습니다"(안전 보장처럼 들리지 않게).
- **결과 누락/불완전**: `analysisComplete`·`clauses`·치수가 없으면 **`[]`로 치환하지 않고** "결과 없음/불완전"으로 분리. 치수 없으면 "위치 표시 불가"(목록만).
- **부분 실패**: "성공한 N/M 페이지에서 발견된 조항"으로 표시. 성공 페이지가 0건이어도 **문서 전체 0건처럼 안내하지 않는다**. 실패 페이지는 표시.
- **재시도**: 서버는 사용자 재분석을 지원하지 않으므로 `retryable`을 재시도 버튼 활성 조건으로 쓰지 않는다. 전체 실패는 오류 요약 + **"새 문서로 다시 분석"** 흐름 안내.
- **이미지 없음**(재진입·세션 만료·스냅샷 폐기): 이미지 없이 목록만 + 안내(우아한 저하). 이미지 로드 상태 = loading / ready / load-error(`onError` 처리).
- **좌표 이상치**: ④의 교집합 클램프 후 표시, 전부 무효면 목록만.

### ⑧ 설정·환경
- 신규 서버 env 없음. Skia 채택 시 네이티브 재빌드 필요(SVG면 불필요).

### ⑨ 고려한 대안
- 오버레이: SVG vs Skia(⑤).
- 재진입 이미지: **세션 한정 localUri**(이번 범위) vs **서버 다운로드 엔드포인트 신설**(비용↑, 저장/재열람과 함께 TASK-006 후속) — 이번은 세션 한정 + 후속 명시.
- 목록↔박스 연동: 공유 선택 상태(store) vs 부모 로컬 상태 — 단순히 로컬 상태로 시작.

### ⑩ 위험
- **좌표 불일치(EXIF)**: 표시 이미지가 upright가 아니면 오버레이 어긋남 → 업로드 시 upright 정규화에 의존, EXIF 1~8 실측으로 검증(필수 Acceptance).
- **이미지 dims 불일치**: 로컬 이미지 intrinsic 크기 ≠ 서버 imageWidth/Height일 수 있음 → 좌표계는 서버 크기 기준, 표시 이미지는 같은 종횡비 보장.
- **세션 한정 이미지**: 재진입 시 이미지 없음 → 우아한 저하 + 후속(다운로드 엔드포인트).
- **Skia 최초 사용**: 채택 시 빌드/런타임 리스크(→ 초안은 SVG로 회피).

### ⑪ 파일·순서 계획 (초안)
1. `lib/coordinateTransform` + 단위 테스트(순수 함수 우선).
2. 위험도 배지 공용 UI + 색 토큰.
3. `HighlightOverlay`(오버레이) → `ClauseList`/`ClauseCard` → `ResultScreen` 조합.

### ⑫ 검증 계획
- **단위**: 좌표 변환 — 가로/세로 레터박스, 소수 배율, viewport 0, 경계 교집합, 완전 범위 밖 박스, 로컬≠서버 치수 불일치, 잘못된 문서/revision 매칭 · 조항 매핑 · 스냅샷 이미지 매칭.
- **컴포넌트·e2e(S20)**: 결과 진입 → 하이라이트 → 조항 탭(다중 박스) 강조 → 페이지 전환 중 늦은 이미지 로드 · 이미지 로드 실패 · 정상 0건 vs 결과 누락 · 부분/전체 실패 · 뒤로갔다 재진입 · 계정 전환 · 새 문서 시작.
- **EXIF 실측**: 모서리별 비대칭 fixture로 1~8 생성, (선택/촬영 → JPEG → 업로드 바이트 → 워커 upright → 앱 표시) 전 경로 iOS·Android 증적. 합성 정답 박스 변환 오차를 수치화하고 OCR 검출 오차와 분리 평가. **합격 기준 = 합성 정답 대비 변환 오차 ≤ 표시 이미지 짧은 변의 1%(또는 ≤ 4pt), 초과 시 실패.** 결과 화면은 서버 upright 박스에 EXIF 재적용 안 함을 확인.
- **재현성·로그**: 고정 서버 응답으로 UI 자동화(실 Vision 경로는 별도 통합 검증). 원문·이미지 URI **canary**로 로그·네트워크 오류 누출 확인.
- 게이트(단위·타입·시나리오) 통과.
