# Feature Guide: 로그인·무료 횟수·구독

## 사용자 목표

사용자가 자신의 무료 분석 횟수와 구독 상태를 확인하고 보호 기능을 사용할 수 있다.

## 관련 도메인

- Auth & Entitlement

## 구현 흐름

1. 앱이 현재 인증 세션을 복원한다.
2. 서버에서 entitlement 정보를 조회한다.
3. 화면에 남은 무료 분석 횟수와 구독 상태를 표시한다.
4. 분석 또는 저장 시 서버가 권한을 다시 검증한다.
5. 권한 부족 응답이면 로그인 또는 구독 안내로 연결한다.
6. 로그인·구독 변경 후 entitlement 쿼리를 무효화하고 재조회한다.

## 무료 차감 정책 (확정 2026-09-30)

서버 분석 결과와 동기화해 차감한다. 앱은 차감을 판단하지 않고 서버 잔량을 표시만 한다.

| 분석 결과 | 무료 차감 |
| --- | --- |
| `done` (전체 성공) | **1회 차감** |
| `partial` (일부 페이지 성공) | 무차감 |
| `failed` (전체 실패) | 무차감 |
| `invalid_image` (손상·초과 등) | 무차감 |

- **차감 시점** = 완료(terminal) 확정 시점(접수 시 아님).
- **멱등키** = `AnalysisJob.id` → 재연결·재시도·중복 완료 이벤트에도 **최대 1회**.
- **동시성 한도 집행·실차감·원자적 예약** = TASK-005 (본 피처의 구현 범위).
- 정책 근거·파이프라인 연동: [0020 spec](../specs/0020-analysis-request-polling.md).

## 보안 규칙

- 민감한 토큰은 안전한 저장소를 사용한다.
- 로그아웃 시 인증 캐시와 사용자별 서버 캐시를 제거한다.
- 다른 계정으로 전환하면 이전 사용자의 문서와 권한을 화면에 남기지 않는다.
- 클라이언트 시계나 로컬 저장값으로 구독 만료를 최종 판정하지 않는다.

## Acceptance Checklist

- [ ] 앱 재실행 시 유효한 세션이 복원된다.
- [ ] 만료 세션은 안전하게 로그아웃 처리된다.
- [ ] 무료 횟수와 서버 차감 결과가 일치한다. *(정책 확정 2026-09-30 — 위 「무료 차감 정책」. 실차감·원자적 예약 구현은 TASK-005에서 체크)*
- [ ] 계정 전환 시 이전 사용자 데이터가 노출되지 않는다.
- [ ] 구독 변경 후 저장 권한이 즉시 재조회된다.
